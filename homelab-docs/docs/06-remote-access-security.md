# Remote Access & Security: Tailscale, SSH, VPN

## SSH

```bash
sudo apt install openssh-server -y
sudo systemctl enable --now ssh
```

Accessed from a mobile device via **Termius**, using the host's
credentials over the local network initially, then over Tailscale for
access from any network.

## Tailscale (WireGuard mesh VPN)

Installed on the host and authenticated to a private tailnet:

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

Any device joined to the same tailnet (including a mobile device
running the Tailscale app) can then reach the host directly over its
Tailscale-assigned IP (`100.x.x.x`), for both SSH and Jellyfin, from any
network, without opening any inbound ports on the home router.

### DNS conflict with Pi-hole

By default, Tailscale manages `/etc/resolv.conf` itself once connected
(**"accept DNS"**), which silently overwrote the host's DNS
configuration that had been pointed at the local Pi-hole instance —
producing a total DNS failure (no site would resolve) that was not
obviously connected to Tailscale at first, since basic connectivity
(`ping`) still worked fine. Diagnosed by inspecting `/etc/resolv.conf`
directly and finding it now generated by Tailscale rather than pointing
at `127.0.0.1`. Resolved by disabling Tailscale's DNS management and
restoring the intended resolver configuration:

```bash
sudo tailscale set --accept-dns=false
sudo bash -c 'echo "nameserver 127.0.0.1" > /etc/resolv.conf'
```

This is documented as a general lesson: **two services independently
managing the same system file** (here, `systemd-resolved` and
Tailscale both wanting ownership of `/etc/resolv.conf`) is a recurring
class of bug worth checking for early in any "everything stopped
working" scenario.

## Tailscale Funnel (public ingress for non-VPN clients)

Devices that cannot run a VPN client at all (e.g. Roku, which has no
mechanism to install third-party networking apps) require a different
approach than joining the tailnet. Tailscale Funnel exposes a single
local service at a public HTTPS URL, without exposing the rest of the
network:

```bash
sudo tailscale funnel --bg 8096
```

This publishes Jellyfin's port at `https://<host>.<tailnet>.ts.net`,
which is then used directly as the server address in Jellyfin's Roku
app. This is a deliberately narrower exposure than traditional router
port forwarding — only the one service, over HTTPS, rather than the
whole host or network.

**Scope note**: Tailscale's terms of service position Funnel for
occasional/developer use cases (exposing a dev server, a webhook
endpoint) rather than as a permanent CDN-style streaming backend. It
works functionally for this purpose but is not represented here as the
"correct" long-term architecture for heavy remote streaming — a proper
reverse proxy (nginx/Caddy) with a real domain would be the next
iteration for that use case.

## General-purpose VPN: ProtonVPN

Installed on the host for outbound privacy on general browsing traffic,
independent of Tailscale (which is inbound/mesh access, not an
outbound privacy tool). Installed via the official Linux **snap**
package after the apt repository route hit a packaging dependency that
was unavailable at the time
(`python3-proton-vpn-local-agent` missing from the repo's package
index) — documented in `07-challenges-and-resolutions.md`.
